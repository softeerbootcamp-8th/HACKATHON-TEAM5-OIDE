# 개발 온보딩 문서 작성

문서화 대상은 `$ARGUMENTS`다. 인자가 없으면 대화에서 합의한 작업과 현재 작업 트리의 변경을 우선 확인한다. 그래도 범위가 여러 기능에 걸쳐 모호하면 문서를 쓰기 전에 사용자에게 범위를 확인한다.

## 목표

이 문서만 읽은 팀원이 다음을 이해할 수 있게 작성한다.

- 무엇을 해결하기 위해 만든 기능인지
- 요청 또는 이벤트가 시작되어 결과가 나올 때까지 어떤 순서로 처리되는지
- 각 클래스, 계층, 데이터 구조가 맡은 책임은 무엇인지
- 주요 설계를 왜 선택했고 어떤 대안을 선택하지 않았는지
- 기능을 사용하거나 확장할 때 어디를 수정하고 무엇을 주의해야 하는지
- 어떤 테스트와 실행 결과로 동작을 검증했는지

## 조사

문서를 쓰기 전에 추측하지 말고 저장소에서 근거를 수집한다.

1. `CLAUDE.md`, `AGENTS.md`, README와 기존 문서 규칙을 확인한다.
2. 명시된 기능 범위와 관련된 소스, 설정, 테스트를 읽는다.
3. `git status`, 관련 diff와 필요한 경우 관련 커밋을 확인해 실제 변경 범위를 파악한다.
4. 진입점부터 최종 응답 또는 부수 효과까지 호출과 데이터 흐름을 추적한다.
5. 테스트가 보장하는 동작과 아직 보장하지 않는 동작을 구분한다.

코드와 테스트에서 확인되지 않는 의사결정 이유를 사실처럼 만들지 않는다. 대화나 기록에 근거가 없으면 코드 구조로부터 도출한 해석임을 밝히거나, 문서의 핵심에 해당하면 사용자에게 확인한다.

## 작성 원칙

- 기본 언어는 한국어로 하고 클래스명, 메서드명, 필드명과 프로토콜 용어는 코드 그대로 쓴다.
- 파일 목록을 나열하는 데 그치지 말고 구성 요소가 연결되는 순서와 데이터 변화를 설명한다.
- 처음 접하는 팀원을 독자로 가정하되 Java나 사용 중인 프레임워크의 일반 문법까지 강의하지 않는다.
- 설계 이유는 해결하려는 문제, 선택한 방식, 얻는 이점, 감수한 제약의 순서로 설명한다.
- 세 개 이상의 구성 요소가 연결되거나 분기가 있으면 Mermaid 흐름도나 시퀀스 다이어그램을 사용한다. 짧은 선형 흐름이면 번호 목록으로 충분하다.
- 코드 예시는 계약이나 사용법 이해에 필요한 최소 부분만 인용한다. 소스 전체를 복사하지 않는다.
- 저장소 내부 파일은 상대 경로로 연결하고, 자주 바뀌는 줄 번호에는 의존하지 않는다.
- 미래 기능을 현재 동작처럼 설명하지 않는다. 미구현 사항은 제한 사항으로 분리한다.

## 문서 구성

내용에 맞지 않는 절은 억지로 만들지 말고 다음 순서를 기본으로 사용한다.

1. **한눈에 보기**: 기능의 목적과 결과를 짧게 요약한다.
2. **배경과 문제**: 기존 문제와 이번 변경의 범위를 설명한다.
3. **전체 처리 흐름**: 시작 조건, 단계별 처리, 성공 결과와 주요 실패 흐름을 보여준다.
4. **구성 요소와 책임**: 핵심 클래스와 데이터 구조가 맡은 역할 및 연결 관계를 설명한다.
5. **설계 결정**: 중요한 선택의 이유, 대안과 트레이드오프를 근거와 함께 적는다.
6. **사용 및 확장 방법**: 호출 예시, 새 항목 추가 위치, 지켜야 할 불변식을 설명한다.
7. **검증**: 관련 테스트 시나리오, 실행 명령과 확인된 결과를 기록한다.
8. **제한 사항**: 의도적으로 제외한 범위와 현재 알려진 제약만 적는다.

기존 문서 디렉터리와 명명 규칙이 있으면 따른다. 규칙이 없으면 `docs/onboarding/<feature-name>.md`에 작성하고 파일명은 영문 kebab-case를 사용한다.

## 완료 전 확인

- 문서에 언급한 경로, 클래스, 메서드, 명령이 실제 저장소와 일치하는지 다시 확인한다.
- 정상 흐름뿐 아니라 이 기능이 직접 처리하는 실패 흐름도 설명했는지 확인한다.
- 설계 이유와 구현 사실이 섞여 독자가 추측을 사실로 오해할 표현이 없는지 확인한다.
- 문서만 읽은 사람이 핵심 흐름을 순서대로 설명하고 안전하게 다음 변경 지점을 찾을 수 있는지 점검한다.
- 문서 외의 프로덕션 코드는 수정하지 않는다.

완료 후 생성하거나 수정한 문서 경로와 확인에 사용한 테스트 또는 명령만 간결하게 보고한다.
